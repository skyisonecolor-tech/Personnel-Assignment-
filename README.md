# 중등 인사 배치 웹앱

정기인사 교과별 인사 배치(결원·충원·신규·강사·비율·점검)를 하는 단일 HTML 웹앱입니다.
서버가 없고, **모든 자료는 사용하는 컴퓨터의 브라우저 안에서만** 처리됩니다.

## 배포 (GitHub Pages)

1. 저장소에는 `index.html`, `README.md`, `.gitignore` 세 파일만 올립니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 `Deploy from a branch`, 브랜치 `main` / 폴더 `/(root)`를 고릅니다.
3. 몇 분 뒤 `https://계정명.github.io/저장소명/` 주소로 열립니다.
4. 새 버전으로 바꿀 때는 `index.html`만 교체합니다. 각 컴퓨터에 저장된 작업 자료는 그대로 남습니다.

## 반드시 지킬 것 (보안 체크리스트)

- [ ] **명부·엑셀·백업 파일(.json)은 저장소에 올리지 않습니다.** `.gitignore`가 막아 주지만, 웹에서 파일을 직접 끌어다 올리면 막히지 않으니 주의하세요.
- [ ] GitHub 계정에 **2단계 인증**을 켭니다. 누군가 계정에 들어와 `index.html`을 고치면 보안 장치를 빼고 자료를 빼돌리는 코드를 넣을 수 있습니다.
- [ ] 저장소 **Settings → Branches**에서 `main` 브랜치 보호(강제 push 금지)를 켭니다.
- [ ] 가능하면 이 웹앱은 **다른 웹앱과 다른 GitHub 계정(또는 조직)**에 올립니다.
  `계정명.github.io` 아래의 모든 페이지는 브라우저 저장소를 함께 씁니다. 이 앱은 저장 자료를 암호화해 두지만, 같은 주소에 다른 앱을 두지 않는 것이 가장 안전합니다.
- [ ] **작업 암호는 잊으면 복구할 수 없습니다.** 작업 후 [저장]으로 암호를 건 백업 파일을 만들어 안전한 곳(개인 PC·보안 USB)에 보관하세요.
- [ ] 공용 PC에서는 작업 후 오른쪽 위 [암호화 저장] 배지를 눌러 **잠그고**, 마지막 사용이라면 관리자 → 데이터 초기화까지 합니다.

## 보안 구성 요약

| 위험 | 대응 |
|---|---|
| 같은 github.io 주소의 다른 페이지가 저장 자료를 읽음 | 브라우저 저장 자료 전체를 **작업 암호로 암호화**(AES-GCM 256비트, PBKDF2-SHA256 60만 회). 암호와 풀린 열쇠는 저장하지 않음 |
| 자리를 비운 사이 열람 | **자동 잠금**(기본 30분, 관리자에서 변경) · 수동 잠금. 잠그면 메모리의 자료도 지움 |
| 백업 파일 유출 | [저장] 파일도 6자 이상 암호로 같은 방식 암호화(암호 없이 저장하려면 한 번 더 확인) |
| 외부로 자료 전송 | 보안 정책(CSP)으로 **모든 네트워크 연결 차단**(`connect-src 'none'`), 외부 스크립트·글꼴·이미지 없음 |
| 주입된 스크립트 실행 | CSP가 **이 파일의 스크립트(해시로 지정)만 실행** 허용. 화면 출력은 모두 글자로만 넣음(HTML 해석 안 함) |
| 다른 페이지가 이 앱을 iframe으로 품기 | iframe 안에서는 실행을 멈춤 |
| 조작된 엑셀·PDF·백업 파일 | 엑셀·인사발령 PDF는 **격리된 작업 공간(Web Worker)**에서 읽고 글자·값만 받음, 시간 제한(엑셀 30초·PDF 90초), 크기 제한(엑셀 20MB·PDF 30MB). 들어온 자료에서 위험한 키 제거, 기본 객체 동결(프로토타입 오염 차단) |
| 인사발령 PDF의 도 전체 명단 | 관외전출 명부와 대조한 결과(발령 교육지원청)만 명부 사람에게 남기고, PDF 명단 자체는 저장하지 않음 |
| 관리자 암호 추측 | 암호 원문은 파일에 없음(솔트+반복 해시, 가짜 해시 5개 섞음). 5회 틀리면 대기 시간이 늘어나고 새로고침해도 유지 |

### 알아 둘 한계

- **관리자 암호는 관리 화면을 막는 문일 뿐**입니다. 공개 저장소의 HTML은 누구나 볼 수 있어, 4자리 숫자는 시간을 들이면 풀 수 있습니다. 명단 보호는 작업 암호(암호화)가 맡습니다. 더 긴 관리자 암호가 필요하면 새로 만들어야 합니다.
- 엑셀 읽기 라이브러리(SheetJS 0.18.5)에는 알려진 취약점(조작된 파일로 인한 프로토타입 오염·처리 지연)이 있습니다. 위 격리·시간 제한으로 피해 범위를 막아 두었고, **출처를 아는 파일만** 올리세요.
- PDF 읽기 라이브러리(PDF.js 3.11.174)의 알려진 취약점(CVE-2024-4367)은 글꼴을 그릴 때 `eval`을 쓰는 경로로 일어납니다. 이 앱은 글자만 뽑고(그리기 없음), `isEvalSupported:false`로 끄고, 보안 정책에서도 `eval`을 막아 두었습니다. 도교육청이 보낸 인사발령 PDF만 올리세요.
- 컴퓨터 자체가 악성코드에 감염됐거나 브라우저 확장 프로그램이 화면을 읽는 경우는 이 앱이 막을 수 없습니다.
